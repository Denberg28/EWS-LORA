# v0.3.0-rc.1 validation gates

Software acceptance requires passing host tests, all three firmware builds, image packaging and checksum checks in GitHub Actions. Hardware acceptance requires the test below on matching physical equipment. Record exact commit, board revisions, routes, RF profile, antenna, power, measured timings and results. Keep private keys and incident coordinates out of published evidence.

| Gate | Evidence |
| --- | --- |
| A — Source/build | Run `./scripts/check.sh` and `pio run -e base -e node -e rover`. GitHub Actions records both |
| B — Behavior | Host tests cover button gesture, rollover, debounce, protocol, authenticated name encoding, v2 record loading, peer clear authority, authenticated route filtering, wrong key, modified packets, stale ACK, relay cooldown/window and per-rover replay classification |
| C — Regression | Host tests cover SOS/CLEAR, sequence reservation, direct ACK and receiver-state restoration. The v2 source and binaries remain on their original tag |
| D — Integration | Simulated direct and one-node round trip in the host tests. USB, NVS, SPI, OLED, radio and GNSS integration are BLOCKED pending physical devices |
| E — HIL/field | BLOCKED pending physical devices. Complete all bench tests before stable promotion |
| F — Delivery | Candidate pipeline must verify merged and application-only images and SHA-256. Physical first flash, upgrade and rollback are BLOCKED pending boards |

## Bench acceptance

Use a Base, at least one Node and two Rovers with attached matched antennas. Provision the Base as ID 0, Node as ID 1, Rover 1 direct, and Rover 2 via Node 1. A second Node with ID 2 is useful for isolation testing. Start with USB power and local serial logs at 115200. Test within authorized RF conditions with a staffed receiver.

1. **Flash and startup.** Flash each merged image at 0x0, provision it via GPIO21 and verify the role and ID. Reset each Rover ten times, including five held-button resets. After leaving bootloader mode, verify there is no unsolicited SOS. Twenty single taps, single long holds and out-of-window gestures must produce zero SOS. A tap shorter than 450 ms followed by a second press within one second must latch within 2.5 seconds of the second press. Continue holding for six seconds and confirm one action.
2. **Direct and routed SOS.** With the network idle for at least 48 seconds, perform ten isolated SOS runs per path. Expect Base saved receipt and Rover ACK within 2 seconds of latch for each clean link run. Node should log exactly one REPORT and one ACK for each routed transaction and zero for a direct request. Tap and hold three seconds to clear. Verify red stays flashing during SOS and while cancellation is pending, including after an SOS ACK. Expect Base CLEAR and Rover solid green within 55 seconds direct or 70 seconds routed, allowing airtime limits, under a clean isolated link.
3. **Relay isolation and outage.** Power off Node 1 and activate Rover 2. Even at direct RF range, the Base must ignore the unforwarded routed request. Restore Node 1 and expect a matching ACK within 55 seconds with Base idle. Repeat with only Node 2 available. Node 2 must not forward Rover 2 traffic assigned to Node 1. Interrupt the Base after relay forwarding and confirm the Node window expires and Rover retries. Repeat on both paths with the Base offline and verify there is no false ACK.
4. **Concurrent incidents.** Activate both Rovers one second apart. Expect two durable Base SOS records and both displayed on the OLED within 120 seconds under a clean two-Rover bench link. Clear one and check the other remains active. Record per-device ACK latency and misses, including a run with two Rovers sharing one Node. Record this shared-node case as capacity data and use it to determine deployment sizing.
5. **GPS and persistence.** Verify SOS without a GNSS fix. Feed synthetic NMEA to Rover GPIO44 via a 3.3 V logic UART adapter using `python scripts/nmea_fixture.py PORT`. Expect +12.50000, +123.50000 within 65 seconds on an isolated path. Stop NMEA and expect NO GPS FIX within 75 seconds. Repeat with real GNSS. Reboot Base with two active alerts and verify restored records. Reboot a Rover with active SOS and pending CLEAR separately, and verify each mode resumes with a higher sequence.
6. **Fault and endurance.** Verify a different-key network is ignored. Check that an old ACK never transitions Rover to ACK SEEN. Check a valid older SOS cannot reopen a durably cleared alert. Interrupt power in both directions and observe recovery. Run the documented routes for eight hours on bench power, record misses and unexpected resets, then repeat over deployment routes and on the actual portable supply. Stable acceptance requires zero lost incident state, zero unexpected resets and at least 99% received scheduled attempts for each isolated clean bench path. Establish a field service boundary and battery runtime using measured results.
7. **Names, peer display and cancellation.** Name Rover 1 ALPHA and Rover 2 BRAVO via USB. Verify names and GPS coordinates appear on the Base and receiving peers. Power off the Base, request a cancellation and verify the sender stays red and the peer keeps the SOS. Restore the Base and verify the sender switches green only after a matching CLEAR ACK. Confirm the peer removes the alert if it hears the confirmed CLEAR, and retains the record if it was offline during confirmation.
8. **Delivery.** On the test boards flash the published role-matched app-only images at 0x10000 and verify NVS configuration retention and normal operation. Reflash the initial images on dedicated clean hardware and exercise the documented baseline rollback in isolation.
